## 二、待办状态机

**这张图是整个系统的骨架。** 所有模块最终都汇到这里。

```
                      ┌──────────────┐
   ⑦ 生成待办 ────────→│   待复核     │
                      └──────┬───────┘
                             │
              ┌──────────────┴──────────────┐
       风控拦截 / AI强否决              放行
              │                             │
              ▼                             ▼
       ┌─────────────┐              ┌─────────────┐
       │   已否决    │              │   待确认    │←── 人在这里看
       └─────────────┘              └──────┬──────┘
                     ┌─────────────────────┼──────────────────┐
                  人确认                人放弃               AI否决
                     │                     │                  │
                     ▼                     ▼                  ▼
              ┌─────────────┐       ┌─────────────┐   ┌─────────────┐
              │   待执行    │       │   已放弃    │   │   已否决    │
              │ 去券商App   │       │ 必须填原因  │   └─────────────┘
              └──────┬──────┘       └─────────────┘
                     │
                  人已下单
                     ▼
              ┌─────────────┐
              │   待登记    │←── 回填券商实际扣的钱
              └──────┬──────┘
                     │
                  登记成交
                     ▼
              ┌─────────────┐
              │   已成交    │   ← 终态
              └─────────────┘
                     │
                     └──→ 写入 journal.jsonl → 重算持仓
```

### 合法迁移表（写在 `ec/todos.py:TRANSITIONS`，不在表里的一律拒绝）

| 从 | 只能到 |
|---|---|
| 待复核 | 待确认、已否决 |
| 待确认 | 待执行、已放弃、已否决 |
| 待执行 | 待登记、已放弃 |
| 待登记 | 已成交、已放弃 |
| 已成交 / 已否决 / 已放弃 | **终态，不可再变** |

**两条硬规则：**
1. **不能跳步。** 待确认 → 已成交 会被拒绝，必须先经过「待执行 → 待登记」。
2. **放弃必须填原因。** 从「待确认」起是人的决定，不是系统的 —— 这个原因是最有价值的复盘数据。

## 三、谁有权改变什么

| 决策 | 谁定 | 代码 | 能否绕过 |
|---|---|---|---|
| 买不买 | 策略规则 | `strategy.py` | 只能靠 `--ignore-signal` 显式覆盖，且**留痕** |
| 买几手 | 风控算 | `risk.py:plan_size` | ❌ |
| 能不能买 | 13 条闸门 | `risk.py` | ❌ |
| 要不要反对 | AI（只能否决） | `ai_review.py` | ❌ |
| 执不执行 | **人** | 待办状态机 | — |
| 什么价成交 | 券商 | — | — |
| 数据能不能信 | `source`/`as_of` 校验 | `pipeline.py` | ❌ 过期即拒绝出单 |

**一句话：规则决定「该不该」，AI 决定「有没有坑」，人决定「做不做」。**

## 四、数据流（哪些文件被读写）

```
读 ─┬─ config.json          唯一需要改的文件
    ├─ ec/pool.py           精选 ETF 池（代码硬编码，含人工确认的 T+0 标记）
    └─ data/todos.jsonl     待办流水账（重放得出当前状态）
       data/journal.jsonl   成交流水账（重放得出持仓和现金）
       data/bars/*.json     日线缓存（当天内不重复请求）

写 ─┬─ data/todos.jsonl      待办事件（只追加，永不修改）
    ├─ data/journal.jsonl    成交事件（只追加，永不修改）
    ├─ data/state.json       持仓快照（缓存，可随时删掉重建）
    └─ out/ticket-*.html     工单
```

**只追加的两本账是这个系统的记账基础。**
理由：直接改状态文件，一旦中途崩溃就会留下一个既不是买入前也不是买入后的
中间态，而且事后无法追溯。只追加的话，状态永远可以重算。

## 五、实际观测到的运行轨迹

### 场景 A：今天没有信号（正常情况，占大多数交易日）

```
[1/7] 数据采集   ok    tencent · 46 只 · 盘前 · 延迟 32421s · 收盘数据
[2/7] 候选池过滤 ok    50 只 → 通过 46 只（排除 4）
[3/7] 持仓体检   skip  空仓，无持仓需要体检
[4/7] 信号扫描   skip  扫描 20 只 → 没有标的满足全部买入条件
[5/7] 风控闸门   ok    0 个候选 → 拦截 0，放行 0
[6/7] AI 复核    skip  已跳过（--no-ai）
[7/7] 生成待办   ok    新增 0 条待办

  今天不需要操作 —— 没有标的满足买入条件
```

> 注意 `盘前 · 延迟 32421s · 收盘数据`：**延迟 9 小时不是故障**。
> 现在是凌晨，拿到的本来就该是昨天收盘价。系统只在**盘中**才判「数据陈旧」。

### 场景 B：有候选但被拦下

```
[5/7] 风控闸门   warn  1 个候选 → 拦截 1，放行 0
      拦截原因：费用占比 往返 10.18 元 = 本笔的 2.29%，超过上限 0.60%
                风险成本比 潜在风险 13.68 元只有往返费用的 1.3 倍，低于要求的 3.0 倍

  今天 1 个候选全部被拦下，不需要动手（原因见待办）
```

## 六、现在真的在跑 vs 还没做

### ✅ 真的在跑（已实测）

| 模块 | 状态 |

## 七、你可以怎么验它

```bash
# 看今天的判断（最常用）
python run.py flow

# 强制走完整链路（会明确标注放宽了哪几条成本闸门）
python run.py flow --code 512000 --demo --ignore-signal --no-ai

# 看队列
python run.py todos

# 看某一条的全部依据
python run.py todos T20261015-01

# 试状态机的拦截（会报错，这是对的）
python run.py todos T20261015-01 --to 已成交      # 待确认不能直接到已成交
python run.py todos T20261015-01 --abandon ""     # 空原因会被拒绝
```
