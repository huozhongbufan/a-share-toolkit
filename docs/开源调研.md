# 开源调研：GitHub 上有什么可用 / 可参考

> 调研方式：GitHub API + README 原文。**未逐个 clone 实测**，star 数和更新时间来自 API。
> 结论按「能不能直接用」分三档。

---

## 一、最重要的发现：我设计里漏了「ETF 溢价」

来源：[`NextRemeber/etf-dca-strategy`](https://github.com/NextRemeber/etf-dca-strategy)（25 轮双周期验证的 A股 ETF 定投体系）

它的每月三个动作里，第三个是：

> **溢价闸门**：纳指溢价 >8% 时改场外申购（按净值成交，而非停买）

**这是真金白银的漏洞。** 跨境 ETF（513050 中概互联、159941 纳指、159632 纳斯达克、
159509 纳指科技、513310 中韩半导体、513120 港股创新药）在场内交易时，
价格可以显著高于基金净值（IOPV）。买在 8% 溢价上，等于**当场亏 8%**。

对比一下量级：

| 成本项 | 对 ¥500 本金的占比 |
|---|---|
| 最低佣金往返 | 2.04% |
| **跨境 ETF 溢价（极端时）** | **可达 8%+** |

**溢价最严重的地方，恰恰是我系统里标记为「T+0 可以当天跑」的那批跨境 ETF。**
我为了风险控制优先推荐它们，却漏掉了它们最大的成本项。

必须新增一条风控闸门：**溢价率闸门**（第 14 条）。

另外这个仓库还有两个值得抄的做法：
- **分数分档定投**：≥90分→3倍 / ≥70分→2x / ≥50分→1x / <50分→0.25x。
  分数 = MA60偏离(50) + 60日动量(30) + BOLL位置(20)，**逆向指标，高分 = 超跌**。
  方向和我现在的趋势跟随**相反** —— 它在跌的时候买更多。
- **三账守恒审计**（现金账 / 份额账 / 财富守恒）：回测引擎的自检方法，比我现在的隐式实现严谨。
- 它**主动声明自己的历史数字作废**（因为修了 4 个引擎 bug），这种诚实值得学。

## 二、可以直接用（三档里的第一档）

### 2.1 Claude Agent Skills —— 最高杠杆的发现

你已经装了 Claude Code 和一堆 skills。这三个是**现成的 A股/量化 Skill**，
正好可以填我设计里标记为「🟡 风险 2：文本层数据源难搞」的那一层。

| 项目 | ★ | 协议 | 一句话 |
|---|---|---|---|
| [`shouldnotappearcalm/a-share-skill`](https://github.com/shouldnotappearcalm/a-share-skill) | 247 | MIT | A股数据分析、量化选股与**模拟交易** Skill 集合。topics 里有 `claude-code` `claude-skills` `mcp` `paper-trading` |
| [`pseudo-longinus/quant-buddy-skills`](https://github.com/pseudo-longinus/quant-buddy-skills) | 193 | MIT | 面向 Agent 投资研究的底层能力，覆盖 A股/港股/美股/期货/宏观/ETF。topics 有 `claude-code` `cursor` `github-copilot` |
| [`MobiusQuant/Gendangzou-skill`](https://github.com/MobiusQuant/Gendangzou-skill) | 308 | Apache-2.0 | 面向 AI Agent 的**可溯源** A 股板块研究 Skill，贯通政策、权威媒体、市场资金、公司与 ETF |

第三个的「**可溯源**」特别对味 —— 我设计里的原则是「AI 只能反对不能加仓」，
那它引用的每条信息都必须能追到出处，否则它的反对意见没法验证。

**这三个直接改变了实施顺序：第 7 步（文本层）从「自己造」变成「装现成的」。**

### 2.2 数据层 —— 解决我标的 🔴 风险 1

| 项目 | ★ | 协议 | 说明 |
|---|---|---|---|
| [`hello245m/free-stockdb`](https://github.com/hello245m/free-stockdb) | 2,876 | 自定义 | 本地量化数据引擎。全市场 7000+ 标的、日/周/月/分钟/tick、复权因子、39 指标、申万+1200概念板块、**五种调用方式含 MCP** |
| [`mpquant/Ashare`](https://github.com/mpquant/Ashare) | 3,904 | **无协议** | 最简行情接口，**新浪+腾讯双源自动故障切换**（和我现有 `quotes.py` 的设计完全一致） |

**`free-stockdb` 的定位和我设计的「本地全市场快照 + 增量更新」一模一样**，
而且它自己算过一笔账：远程 API 方案做全市场分钟线回测要 10-15 个工作日才能跑通，
「不是慢，是跑不通」。

**但我有三个顾虑，必须先验证再决定采不采用：**

1. **它是 C++ 二进制发行包**，不是纯 Python。引入后我的「零依赖」就不再成立。
2. **它默认从 `sync_url.txt` 指向的第三方同步节点拉数据**，数据源不完全自主。
3. ⚠️ **README 里的下载地址之一是裸 IP**（`http://1783355894`）。这不是正常的发布方式。
   正式发布应该走 GitHub Releases。**这一点我必须明确提醒你，不要点那个链接。**

`Ashare` 的 `stargazers_count` 是 3904 但**没有 LICENSE 文件** ——
法律上属于「保留所有权利」，**代码不能直接抄进你的项目**（尤其你还打算开源）。
可以参考它的实现思路，但不能复制代码。

### 三个可以直接采纳的技术点

**① 动量算法（来自 etf-momentum-board）**
> 20 日对数价格加权最小二乘回归求斜率 → 指数年化 → **乘以加权 R² 作为趋势质量惩罚**

我现在用的是朴素的「20 日收益率」。它的做法多了一层 **R² 惩罚**：
涨得猛但走得不稳的标的会被扣分。这正好治我的病 ——
我的回测胜率只有 25%，说明进场质量差。**建议采纳。**

**② 多指标共振（来自 Resonance）**
> 五个指标各自亮灯，**同色灯 ≥3 盏才判定**

我现在是加权打分（动量 50% + 趋势 30% + 便宜度 20%）。
加权打分的缺点是**一个极端值能盖过其他所有信号**。
改成「多指标投票、过半才通过」更稳健。**建议采纳为打分层的替代方案，回测对比。**

**③ 市场规则注册表（来自 tickflow-stock-panel）**
它的 `markets.py` 把印花税、涨跌停、最小交易单位、T+N 交收、价格精度收敛到一处，
并且明确标注了哪些被真正调用、哪些还是脚手架。**和我设计的 `instruments.py` 撞了** ——
这是个好信号，说明抽象方向是对的。可以直接参考它的字段划分。

## 四、必须避开的坑（实证）

### AKShare 的 `stock_zh_a_spot_em` 会封你的 IP

[Issue #6061](https://github.com/akfamily/akshare/issues/6061)（已关闭，标签 `bug`），报告者原文：

> 按 **10 秒周期**运行 `df = ak.stock_zh_a_spot_em()`，过一会就会出现报错
> **解决方案：更换公网 IP 后，akshare 接口恢复正常**；修改源代码，**降低异步并发数量**
> 「免费的服务要省着点用！」

报错是 `ServerDisconnectedError: Server disconnected` —— **和我实测遇到的
`RemoteDisconnected` 是同一件事**。而且源码显示它用的正是
`https://82.push2.eastmoney.com/api/qt/clist/get`，**和我的 `fetch_etf_list()` 打的是同一个接口**，
区别是 AKShare 用了 `aiohttp` 异步并发，**比我更激进**。

**结论：AKShare 不是这个问题的解药，它是同一个坑的高配版。**

受影响接口不止一个：`stock_zh_a_spot_em`、`stock_board_concept_name_em`、
`stock_individual_fund_flow_rank`、`stock_zh_a_spot`。

`oficcejo/aiagents-stock`（2009★）的 README 也自己警告：
> 「测试云服务访问过多，**数据源有可能会拒绝**，如需使用，请部署本地。」

**这印证了我把「全市场列表接口」标成 🔴 风险 1 是对的，而且比我以为的更普遍。**

## 五、协议风险（你要开源，这条很重要）

你之前把 codex-multi-provider 发到 GitHub 了，这个项目大概率也会发。**那协议就不能不注意：**

| 协议 | 项目 | 能不能参考思路 | 能不能抄代码 |
|---|---|---|---|
| MIT / Apache-2.0 | 大部分 | ✅ | ✅（保留版权声明） |
| **AGPL-3.0** | QuantMind | ✅ | ⚠️ **传染性**，你的项目也得 AGPL |
| **无协议** | Ashare、PanWatch 之外几个 | ✅ | ❌ **法律上「保留所有权利」，不能抄** |

**建议：只 MIT / Apache-2.0 的代码可以参考实现，AGPL 和无协议的只看思路。**

## 六、这些项目改变了什么

### 不用自己造的（省下来的时间）

| 层 | 原计划 | 改成 |
|---|---|---|
| 文本层（第 7 步） | 自己做公告/新闻结构化 | **装现成的 Claude Skill**（a-share-skill / Gendangzou） |
| 全市场数据 | 自己写快照 + 增量更新 | **先评估 free-stockdb**（但有三个顾虑待验证） |

### 必须改的设计

| # | 改动 | 来源 |
|---|---|---|
| 1 | **新增「溢价率闸门」风控规则**（第 14 条） | etf-dca-strategy |
| 2 | 动量指标加入 **R² 趋势质量惩罚** | etf-momentum-board |
| 3 | 回测引擎加 **三账守恒自检** | etf-dca-strategy |
| 4 | 打分改为**多指标投票**（与加权打分做 A/B 回测） | Resonance |
| 5 | 第 7 步从「自建文本层」改为「先评估现成 Skill」 | a-share-skill 等 |

### 不变的定位

PanWatch（2115★）、aiagents-stock（2009★）这些高星项目做的是
**「AI 帮我选股/荐股/盯盘」**——让 AI 做预测。

我们做的是 **「AI 当风控复核员，规则管纪律」**——让 AI 挑毛病，不让它做预测。

**定位不变。但数据层和 Skill 层应该复用，不该重造。**
一句话总结这次调研：**自建的应该是决策与纪律层，而不是数据和文本层。**
