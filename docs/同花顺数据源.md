# 同花顺数据源

> 起因：「把信息源改成桌面上的同花顺，省得到处找」
> 结论：**本地代码表完美可用（离线、零请求、7682 只）；行情接口实测可用且与腾讯逐字段一致；
> 但本地那个实时缓存文件不能用。**

---

## 一、桌面上的同花顺有什么

安装目录 `C:\同花顺软件\同花顺`（快捷方式指向 `hexinlauncher.exe`）。

| 位置 | 内容 | 能用吗 |
|---|---|---|
| `stockname\stockname_16_0.txt` | **上海全市场代码表**（GBK 文本） | ✅ **完美** |
| `stockname\stockname_32_0.txt` | **深圳全市场代码表**（GBK 文本） | ✅ **完美** |
| `history\<市场>\day\*.day` | 本地日线缓存 | ⚠️ 只有 10 个文件，是按需下载的碎片 |
| `realtime\<市场>\stocknow.dat` | 实时行情缓存（`hd1.0` 私有格式） | ❌ **不可用**，见第三节 |
| `stockname\_*_1.txt` | 历史名称表（`@h1`/`@h2` 是曾用名） | ⚠️ 别读，会用旧名覆盖新名 |

## 二、✅ 本地代码表：这解决了最大的问题

文件是纯文本，格式：

```
600519=贵州茅台|贵州茅台@f
510300=沪深300ETF华泰柏瑞|沪深300ETF华泰柏瑞@f
```

**按段落分品种**（这张表是实测出来的）：

| 文件 | 段落 | 条数 | 内容 |
|---|---|---|---|
| `16_0.txt` | `16_16` | 203 | 指数（1A0001 上证指数） |
| | `16_17` | **2238** | **上海A股** |
| | `16_18` | 42 | B股 |
| | `16_19` | 22693 | 债券 |
| | `16_20` | **1375** | **上海场内基金** |
| | `16_22` | **84** | **ST股** ← 单独成段，直接拿来排雷 |
| `32_0.txt` | `32_32` | 378 | 指数 |
| | `32_33` | **2908** | **深圳A股** |
| | `32_34` | 39 | B股 |
| | `32_35` | 20273 | 债券 |
| | `32_36` | **1165** | **深圳场内基金** |
| | `32_37` | 2 | 退市股 |

**实测取到的结果：**

```
数据日期 : 20261014          ← 当天最新（ConfigVer 前缀就是日期）
可交易   : 7682 只  {股票: 5144, ETF: 1723, 基金: 458, LOF: 357}
风控排除 : 84 只 (ST + 退市)  ← 不用猜名字里有没有 ST，它单独成段

抽查：
  sh600519  贵州茅台          [股票]
  sz000001  平安银行          [股票]      ← 不是「深发展A」
  sh510300  沪深300ETF华泰柏瑞  [ETF]
  sh588096  科创50ETF华夏      [ETF]
```

**为什么这一条最重要：**
- **零网络请求** —— 没有限流、没有封 IP 的风险（东财那个接口连续 4 次就掐断）
- **完全离线** —— 断网也能用
- **分类现成** —— 股票/ETF/基金/LOF 分好了，ST 和退市单独一段
- **数据新鲜** —— `ConfigVersion` 前缀就是日期，可校验

原来我维护的是一份 **50 只的硬编码 ETF 池**。现在是 **7,682 只的本地权威表**。

## 三、❌ 本地实时缓存不能用

`realtime\shase\stocknow.dat`（14.4 MB）看着很诱人，但：

1. **私有二进制格式。** 文件头是 `hd1.0`，后面是变长记录加标签，
   不是常见的 32 字节 TDX 格式（试过，解出来全是 -1 和 NaN）。
   要逆向，而且**同花顺一升级就可能失效**。

2. **只在客户端运行时才更新。** 实测检查时：
   ```
   stocknow.dat 最后修改  2026/10/14 12:40:16
   当前时间              2026/10/15 01:21:54
   → 已过期 12.7 小时
   ```
   那个时间点是**午休时段**，说明同花顺 12:40 之后就没在运行了。
   依赖它的前提是「同花顺必须一直开着」。

3. **拿不到比公开接口更新的数据。** 下面第四节的接口给的是同样的数据。

**结论：不采用。**

## 四、✅ 同花顺公开行情接口：实测可用

同花顺自己的行情域名 `d.10jqka.com.cn` 是公开的。实测：

| 用途 | 地址 | 结果 |
|---|---|---|
| **实时快照** | `/v6/line/hs_<代码>/01/today.js` | ✅ 283 字节/只 |
| **日线** | `/v6/line/hs_<代码>/01/last.js` | ✅ 140 条 ≈ 6 个月 |
| 日线（按年） | `/v6/line/hs_<代码>/01/<年份>.js` | 待测 |
| **分时** | `/v6/time/hs_<代码>/last.js` | ✅ 逐分钟 |
| **五档盘口** | `/v6/realhead/hs_<代码>/last.js` | ✅ |
| ~~实时快照（旧）~~ | `qd.10jqka.com.cn/quote.php` | ❌ 401 |

### 字段格式（已解开并核对）

**实时快照** `today.js`：
```
{"hs_600519":{"1":"20261014","7":"1270.10","8":"1286.75","9":"1266.00",
              "11":"1286.00","13":2377273,"19":"3045608000.00", ...}}
   1=日期  7=开盘  8=最高  9=最低  11=现价  13=成交量(股)  19=成交额(元)
```

**日线** `last.js`：`data` 是按 `;` 分记录、`,` 分字段的字符串
```
20261014,4.336,4.351,4.284,4.294,886444480,3827820700.000,3.590,,740400.000,3179277.6
 日期     开     高     低     收     成交量(股)    成交额(元)     换手%
```

### 与腾讯源交叉核对（这是关键验证）

`sh510300` 在 `20261014`：

| | 现价 | 成交量 | 成交额 |
|---|---|---|---|
| 腾讯 | 4.294 | 8,864,445 手 | 382,782 万 |
| 同花顺 | 4.294 | 8,864,445 手 | 382,782 万 |
| **一致** | ✅ | ✅ | ✅ |

**三个字段完全相同。** 所以换源不会引入数据口径差异。

## 五、限制：同花顺一次只能查一只

批量请求实测 404：
```
/v6/line/hs_600519,hs_510300/01/last.js   →  404
```

这意味着**不能**用同花顺做全市场扫描（7,682 只就是 7,682 次请求）。

### 所以分工是：

| 场景 | 用哪个源 | 理由 |
|---|---|---|
| **全市场代码表** | **同花顺本地文件** | 零请求，最全，带分类 |
| **全市场批量扫描** | **腾讯** `qt.gtimg.cn` | 60 只/请求，7,682 只 ≈ 128 次请求 |
| **单只精确查询** | **同花顺** | 带五档、分时，且与腾讯数据一致 |
| **兜底** | 新浪 | 两个都挂的时候 |

**这不是「换成同花顺」，是「各用各的长处」。**
同花顺解决的是「全市场清单从哪来」和「精确查询」，
腾讯解决的是「批量」。

## 七、下一步要你定的

本地代码表已经能用了，但**接进 `universe.py` 是个行为变化**：

- 现在：候选池 = 50 只人工维护的 ETF（带人工确认的 T+0 标记和分类）
- 接上后：候选池 = 7,682 只本地全市场，靠规则过滤

两种做法：

| 方案 | 说明 |
|---|---|
| **A** | 用同花顺表做权威全市场，`ec/pool.py` 降级为「优先观察名单」（人工确认过 T+0 的那批排前面） |
| **B** | 保持现在的 50 只精选池，同花顺表只用来**扩充**和**校验名称** |

我倾向 **A** —— 7,682 只里靠「买得起 + 流动性 + 排除 ST/退市」自动筛，
比人工维护 50 只更完整，而且 ST 是现成单独一段，排雷更准。
但要先确认一件事：**¥500 下从 7,682 只筛出来的东西，和从 50 只里筛出来的，
哪个更靠谱？** 这个得跑数据看，不能拍脑袋。
