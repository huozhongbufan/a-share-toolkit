# 本地模型常驻（不要让 AI 闲着）

> **一条命令：** `python run.py warm --models qwen3.5:4b`
> 效果：`ask` 从 **4.2 秒 → 1.5 秒**，`look` 也变快。

---

## 🔴 两个重要更正

### ① 这台机器有独立显卡，一直在用 GPU 推理

我一开始按 CPU 估算，这是错的。服务日志里写得很清楚：

```
id=0 library=CUDA compute=8.9 name=CUDA0
description="NVIDIA GeForce RTX 4070 Laptop GPU"
total="8.0 GiB" available="6.9 GiB"
```

**所以瓶颈不是系统内存，是显存。** 这两个是完全不同的资源：

| | 大小 | 说明 |
|---|---|---|
| 系统内存 | 15.7 GB（可用 ~4.6） | 不影响模型加载 |
| **显存** | **7948 MiB 可用** | **真正的约束** |

### ② `qwen3.5:4b` 也会调工具

之前写「只有 qwen2.5:7b 会调工具」是**错的**。实测：

```
qwen3.5:4b  tool_calls=1 → get_quote(['农业银行']) → 回答正确
```

所以它一个模型能干两件事：**读图（`look`）+ 调工具（`ask`）**。
这意味着显存不够时，**不需要在两者之间取舍**。

---

## 显存账：为什么只能常驻一个

```
qwen3.5:4b   3783 MiB
qwen2.5:7b   4675 MiB
两者相加     8458 MiB   >   可用 7948 MiB     ← 差 510 MiB
```

**只差 510 MiB，就是装不下。** ollama 会挤掉前一个，换后一个。

```
载入 4b → 模型: [qwen3.5:4b]  显存 used 3783 / free 4166
载入 7b → 模型: [qwen2.5:7b]  显存 used 4675 / free 3274   ← 4b 被挤掉
```

**所以选一个就够了，而 `qwen3.5:4b` 是唯一一个能同时覆盖两条路径的：**

| | qwen3.5:4b | qwen2.5:7b |
|---|---|---|
| 读图 `look` | ✅ **唯一有视觉的** | ❌ |
| 调工具 `ask` | ✅ 1.5~1.7s | ✅ 1.1s |
| 显存 | **3783 MiB** | 4675 MiB |
| 结论 | **✅ 常驻这个** | 只在需要时临时用 |

## 环境变量（已设为用户级，持久生效）

```powershell
OLLAMA_MAX_LOADED_MODELS = 3      # 允许同时加载 3 个（但显存装不下，见上）
OLLAMA_KEEP_ALIVE        = -1     # 永不自动卸载
```

**踩过的坑**：`Start-Process` 启动的子进程继承的是**启动那一刻**的环境变量。
先 `SetEnvironmentVariable(..., 'User')` 再 `Start-Process`，新变量不会自动生效 ——
必须在**当前进程**里先 `$env:XXX=...`，再启动子进程。

**验证方法**：看服务日志里的 `server config env="map[...]"`，会打印实际生效的值。

## 实测收益（对照实验）

| 命令 | 冷启动（在磁盘） | 热启动（在显存） | 省 |
|---|---|---|---|
| `ask`（工具调用） | **4.2s** | **1.5s** | **64%** |
| `look`（读图） | **8.2s** | **5.3s** | 34% |

`look` 只省 1.5 倍，因为它的时间大头是 PowerShell 截图 + 视觉推理，不是加载模型。

---

## 为什么 ollama 默认会卸载

`OLLAMA_KEEP_ALIVE` 默认 5 分钟 —— 五分钟没人用就卸载，下次要重新加载。

设成 `-1` 之后，实测：

```
加载后：  qwen3.5:4b  3.14 GB  expires_at = 2319-01-30   ← 等于永不卸载
20 秒后： （还在）
```

而且**之后不带 keep_alive 的普通请求不会把它改回 5 分钟**（测过）。

## 用法

```bash
python run.py warm --list                    # 看当前状态 + 档位
python run.py warm --models qwen3.5:4b       # ✅ 推荐：读图+工具都覆盖
python run.py warm --models qwen2.5:7b       # 只要工具调用，快 0.4 秒
python run.py warm --set find                # 钉 deepseek-r1:8b（检索）
python run.py warm --unload                  # 释放
```

输出：


## 能不能全都常驻

**不能。** 五个模型磁盘上 19.9 GB，显存只有 7948 MiB。

就算关掉所有娱乐应用腾出内存也没用 —— **瓶颈是显存，不是内存。**

唯一能腾显存的办法是让某个模型跑在 CPU 上（`OLLAMA_LLM_LIBRARY` 或部分 offload），
但那会让推理慢 5~10 倍，得不偿失。

---

## 两个设计决定

### ① 内存/显存不够时自动腾地方

用户不该被要求「先 `--unload` 再 `--set`」。`pin()` 发现不够时会先释放**不是这次要钉的**模型。

### ② 宁可拒绝，不去 swap

如果腾完还是不够，**明确报错并算出差多少**，不硬加载。
一旦进 swap 或部分 offload，每次推理都要换页 —— **比卸载重载还慢**。

---

## 什么时候该用

| 场景 | 建议 |
|---|---|
| 今天要频繁 `ask` / `look` | `--models qwen3.5:4b` |
| 只要查行情，不读图 | `--models qwen2.5:7b`（快 0.4s） |
| 偶尔用一次 | **不用开**，冷启动 4 秒可接受 |
| 长时间不用电脑 | `--unload` |

---

## 一句话

**「实时在线」的代价是 3.8 GB 显存，而这块 4070 有 7.9 GB 可用。**

够放一个，放不下两个 —— 所以选那个能一个顶两个的。
